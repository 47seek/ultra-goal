# Ultra-Goal

[English](./README.md) | [中文](./README_cn.md)

> 面向 Codex、Claude Code 等 Agent 的任务协作 Skill，用于完成持续数小时乃至数天的复杂任务：先调研并制定计划，经使用者确认后分阶段自主推进，仅在必要时暂停。

## 安装

通过 `skills` CLI 安装：

```bash
npx skills add Azure99/ultra-goal --skill ultra-goal
```

亦可要求 Agent 直接安装：

> Install `ultra-goal` from <https://github.com/Azure99/ultra-goal>.

## 使用方式

本 Skill 不会自动触发，须由使用者在请求中显式调用，例如：

> 使用 ultra-goal 完成以下目标：将本项目由 Express 迁移至 Fastify，保持现有 API 行为不变，所有现有集成测试与 E2E 测试须继续通过。

涉及代码修改的任务须在 git 仓库内执行，因为实施期将按阶段进行本地提交；若当前目录不在 git 仓库内，主 Agent 会在首批问题中询问是否初始化。非代码任务以检查点代替提交。

## 工作流程

主 Agent 负责推进全程，调研、review 等工作可委派给子 Agent。

1. **调研**：查明现状并验证关键方案；需由使用者决定的问题集中提出，并附候选方案与推荐方案，使用者可答复「其余按推荐」。
2. **计划确认**：总体计划明确交付内容、验收标准与阶段划分，提交使用者确认；push、部署等需单独授权的操作可于此时一并授权。
3. **分阶段实施**：各阶段依次完成阶段计划、实施与验证、独立 review 及本地提交，无需逐阶段请示。
4. **整合交付**：完成整合 review 与整体验证后，向使用者汇报。

实施期间，仅当出现须由使用者处理的事项（待决问题、授权需求或阻塞）时才会暂停，且会先完成不依赖这些事项的工作。对于小而明确、且使用者要求直接完成的任务，采用简化流程。

每个任务的过程记录保存于 `ultragoal/YYYY-MM-DD-task-name/`，用于中断后接续及检索历史任务，不纳入产品提交。

## 适用场景

Ultra-Goal 适用于持续数小时以上的复杂任务，如大型重构、跨技术栈迁移、从零构建完整模块，以及调研报告、技术方案等非代码交付，尤其适合使用者无法持续跟进的情形。每次运行均会在调研、review 与记录上消耗 token，因此「添加按钮」「修正拼写错误」等局部改动不宜使用。

主 Agent 应使用当前能力最强的模型，模型能力不足易导致流程偏离目标。子 Agent 的模型默认由平台决定；如需控制成本，可在请求中指定较小的模型。

## 目标编写建议

- **明确目标与验收标准，不预设实施步骤。** 以具体步骤描述目标（如「第一步修改 `server.ts`」）会压缩探索与规划空间，可能降低结果质量；目标过于模糊时，主 Agent 会在调研期先询问一两个决定方向的问题。
- **尽可能提供端到端验收方法。** 仅依赖单元测试通常不足，测试通过并不代表功能可用。Web 应用可使用 `playwright-cli` 驱动真实浏览器验证关键路径；CLI 工具应执行真实命令，校验标准输出、退出码与生成文件；服务端 API 应启动真实服务进程，使用 `curl` 验证关键接口。

## 设计理念

Spec-Driven Development 已成为 AI 辅助开发的事实标准，但仍存在三个痛点。Ultra-Goal 的应对方式如下：

| 痛点 | 应对方式 |
| --- | --- |
| 关键实现决策仍需使用者逐一裁定 | 可查证的事实自行查证，常规专业判断自行决定并记录；仅就使用者独有的信息、实质影响结果的取舍及授权事项征询使用者 |
| 超长程任务无法在实施前写尽 spec | 总体计划确定方向，阶段细节于各阶段开始时依据实际状态制定 |
| 计划中途被证明不可行时，回退与重规划成本高 | 不影响已确认范围的偏差由主 Agent 自行调整并记录原因，影响范围时方提交使用者裁决 |

## 从 v1.x 升级

<details>
<summary>升级说明</summary>

- **移除 `prepare-ultra-goal` 与 `ultra-goal-heavy`。** 目标澄清已并入调研期；多路独立规划与交叉评审不再单独提供，如需更多 review，可在请求中说明。
- **改为集中提问、按需暂停。** v1.x 进入执行后不再询问使用者；新版在调研期集中提问，计划就绪后等待确认，实施中遇到须由使用者处理的事项时亦会暂停。
- **记录目录调整为 `ultragoal/YYYY-MM-DD-task-name/`。** 其结构与 v1.x 的 `ultragoal/<goal-name>/` 不同。

卸载旧版 Skill（如为全局安装，请添加 `-g`）：

```bash
npx skills remove prepare-ultra-goal ultra-goal-heavy
```

</details>
